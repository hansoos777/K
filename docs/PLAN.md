## 0. 서비스 컨셉 (이름과 목적)

- **이름 "믿어보까"(2026-11-04 확정)**: "믿어볼까?" 하고 가볍게 물어보는 말맛의 이름. 종교와 문화를 둘러보고 배우는 곳. 재치는 이름에만 두고, 서비스 안은 장난스럽지 않게 차분하고 정중하게 간다.
- **톤**: 이름은 가볍게 웃음을 주되, 서비스 안은 장난스럽지 않게 차분하고 정중하게. 캐릭터·게임화·유행어를 쓰지 않는다. 위트는 이름(로고)에서만.
- **목적**: 각 종교를 **체험하고 배우는** 곳. 처음 접한 사람이 이곳에서 예절과 흐름을 익힌 뒤 **실제 교회·성당·절·사원에 가서 당황하지 않고 잘 따를 수 있게** 하는 입문 준비 공간이다.
  - 그래서 3D 공간의 동작(앉기·절·성호·합장·향·초)과 안내는 실제 현장의 순서와 예절을 그대로 따른다.
  - 신앙 활동의 "실제로 하는 방법"은 오프라인에서 그대로 쓸 수 있는 단계로 쓴다.
  - 가상 체험이 실제 예배·미사·법회·푸자를 대신한다고 말하지 않는다.
- **콘텐츠**: 종교별 소개·교육 내용은 사용자가 보강 자료를 줄 예정이다. `src/learn/<종교>.ts`에 넣으면 화면 코드는 바꾸지 않아도 된다.

## 5. 추천 아키텍처: 모듈형 모놀리스

```
src/
  core/         공통: store(저장), router, audio, perf(측정), registry(공간 등록부)
  i18n/         공통 문구 ko(기본) / en(지연 로딩)
  ui/           공통 UI: Home, Settings, WorldShell(지연 로딩·오류 처리), kit(WorldFrame·Panel…)
  worlds/
    christian/  meta.ts(장소 이름, 홈에서 씀) · World.tsx · scenes.tsx · strings.ts
    catholic/   + calendar.ts(전례력 계산)
    mandir/     PujaTime 브리지 → 2단계에 PujaTime 소스
    temple/
```

- 새 공간 추가 = `worlds/<id>/` 폴더 + `registry.tsx`에 한 줄. 코어는 월드 안쪽을 모른다.
- 각 월드는 `React.lazy`로 **들어갈 때만** 다운로드되고, 나가면 소리 노드를 정리하고 오디오 장치를 쉬게 한다.
- 서버가 필요해질 때(2단계)도 **하나의 Cloudflare Worker** 안에서 `/api/auth`, `/api/sync` 경로로 나눌 뿐 마이크로서비스로 쪼개지 않는다.

## 6. 추천 기술과 이유

| 필요 | 추천 | 대안과 비교 |
|---|---|---|
| 정적 호스팅·CDN | **Cloudflare Pages** | 정적 요청·대역폭 무료, PujaTime이 이미 사용 중 |
| 대용량 미디어(3D·녹음) | **Cloudflare R2** + 사용자 도메인 캐시 | 인터넷 전송(egress) 무료. S3+CloudFront는 전송량 과금 |
| API | **Cloudflare Workers** (필요할 때만) | 상시 서버 없음, 요청당 과금 |
| DB | **Cloudflare D1** (SQLite) | 사용자 설정·즐겨찾기·기도 노트 동기화에 충분. 관계형 요구가 커지면 Postgres(Supabase 등)로 이전 가능하게 SQL 표준만 사용 |
| 로그인 | Google·Kakao·Apple OAuth를 Worker에서 직접 처리 | 외부 인증 서비스 비용·종속 없음. 개발 부담이 크면 Supabase Auth(무료 5만 MAU)를 검토 |
| 3D(3단계 이후) | **three.js** (해당 월드 청크에만 포함) + glTF·meshopt·KTX2 | 게임 엔진(Unity WebGL 등)은 초기 다운로드 수십 MB → 부적합 |
| 실시간 공동 방문(5단계) | Durable Objects, 방(room) 단위 | 필요한 공간에만, 인원·전송 빈도 제한 |

## 7. 비용 구조와 세 가지 대안

### 확인한 가격 (2026-11 기준, 공식 가격표)

- **R2**: 저장 $0.015/GB-월, 쓰기(Class A) $4.50/백만, 읽기(Class B) $0.36/백만. 무료: 10GB-월, Class A 100만, Class B 1,000만/월. **인터넷 전송 무료**.
- **Workers Paid**: 월 $5 최소. 요청 1,000만/월 포함(초과 $0.30/백만), CPU 3,000만 ms 포함 (요청·CPU 포함량은 제3자 계산기 기준, 공식 페이지에서 다시 확인 필요).
- **D1**: 무료는 하루 읽기 500만 행·쓰기 10만 행·5GB. 유료는 월 읽기 250억 행·쓰기 5,000만 행·5GB 포함, 초과 쓰기 $1/백만 행, 저장 $0.75/GB-월. 전송 무료.
- **Supabase**(대안): 무료 5만 MAU, Pro $25/월부터 10만 MAU 포함.
- **Pages 정적 파일**: 요청·대역폭 무료.

### 가정

- MAU 1명이 한 달에 8번 방문, 평균 2개 공간 입장
- 1단계: 첫 화면 81KB(gzip), 공간당 3~10KB → 사실상 0원
- 3D 도입 후: 공간당 3~8MB(모바일 기준 예산), 브라우저 캐시 후 재다운로드 없음, R2 앞에 Cloudflare 캐시를 둬 Class B 호출 대부분을 캐시가 받음
- 2단계 API: MAU당 월 약 100회 요청, 쓰기 약 20행

### 월 예상 비용 (도메인 비용 제외, 단위 USD)

| MAU | A. 최소 비용형 | B. 균형형 | C. 확장형 |
|---|---|---|---|
| 구성 | Pages + localStorage, 미디어는 R2 | A + Workers Paid + D1 + 직접 OAuth | B + 실시간 방(Durable Objects) + 오류 모니터링 |
| 100 | **$0** | **$5** (최소 요금) | $5 + α |
| 1,000 | **$0** | **$5** | $5 + α |
| 10,000 | **$0** (R2 무료 범위) | **$5** (요청 100만 ≪ 포함 1,000만) | $5~ + 실시간 사용량 |
| 100,000 | $0 ~ 수 달러 (R2 캐시 미스가 많을 때 Class B 초과) | **약 $5~10** (요청 ~1,000만, 쓰기 ~200만 행 → 포함량 근처) | **산정 불가**: 실시간 접속 시간·메시지 수에 따라 크게 변함 → 실측 후 산정 |
| 한계 | 기기 간 동기화·로그인 없음 | 공동 예배·실시간 기능 없음 | 운영 복잡도 증가 |

추천: **지금은 A, 로그인이 필요해지면 B**. C는 공동 방문 수요가 실제로 확인될 때만 공간 단위로 붙인다.

### 비용 급증 방지

- Cloudflare 계정에 사용량 알림, R2·Workers에 월 예산 알림 설정
- Worker에 IP·사용자별 요청 제한, 재시도 최대 2회·타임아웃 5초
- 실시간 방: 방당 인원 상한, 위치 업데이트 초당 최대 2회, 비활성 60초 후 연결 끊기
- AI 기능을 넣더라도 미리 작성한 안내문을 우선 사용, 결과 캐시, 사용자별 일일 한도

## 9. 데이터·리소스 용량 관리

- **공간별 독립 로딩**: 이미 구현됨(빌드 결과 `World-*.js`가 공간마다 따로 있음, 테스트에서 들어갈 때만 다운로드되는 것을 확인).
- **3D 예산(모바일)**: 공간당 다운로드 5MB 이하, 삼각형 10만 개 이하, 텍스처 최대 1024px(KTX2), 그림자는 구워서(baked) 사용, 실시간 조명 1~2개, 공통 오브젝트(촛불·의자·등)는 인스턴싱.
- **이미지**: AVIF/WebP, 썸네일·원본 분리, `srcset`.
- **오디오 녹음**(허가 확인된 것만): Opus 64~96kbps, 들을 때만 다운로드, R2 + 장기 캐시.
- **캐시 정책**: `public/_headers`. 해시 붙은 빌드 파일은 1년 immutable, `index.html`은 no-cache. 사용자 데이터는 캐시하지 않음.
- **DB**: 미디어 파일은 DB에 넣지 않고 R2 경로만 저장.
- **측정**: `npm run size`로 빌드마다 전송량 확인, 설정 > 진단에서 TTFB·FCP·LCP·공간 로딩 시간 확인(외부 분석 서비스 없음).

### PujaTime 3D 구현 방식 (이전 작업 기록 기준, 소스 미확인)

- three.js 기반. `src/three/shrine.ts`(내 신당, 고정 시점), `hall.ts`(공용 사원 홀, 바닥 터치 이동·드래그 시점), `devotee.ts`(2등신 캐릭터: 사리·쿠르타, 합장·절), `decor.ts`(금 토라나, 후광, 금잔화 줄, 랑골리, 깃발, 큰 종, 칼라시)
- 금속은 PMREM 환경맵 대신 매트캡(페이지 멈춤 문제 때문) → **믿어보까도 같은 방식을 채택**
- 신상: FLUX.1 schnell(Apache 2.0) 이미지를 카메라를 향하는 판으로 표시, TRELLIS.2(MIT)로 입체 GLB 시도 중
- 결론: 엔진·카메라·캐릭터 방식이 믿어보까와 같은 계열이라 **힌두교 모듈로 옮기기 쉽다.** 신상·사원 장식은 PujaTime 것을 그대로 쓰고, 믿어보까의 조이스틱·튜토리얼·안내 지점만 연결하면 된다.

### 3D 공간 제작 방식

| 방식 | 장점 | 단점 | 지금 |
|---|---|---|---|
| **코드로 만드는 절차적 3D** (지금) | 파일 다운로드가 거의 없음(공간당 수십 KB), 저작권 걱정 없음, 바로 수정 | 아주 섬세한 조각·인체는 한계 | 모든 건축 구조 |
| **Blender 등으로 만든 GLB 모델** | 조각·신상·성상 같은 정교한 형태 | 공간당 수 MB, 제작 시간·비용, 라이선스 확인 필요 | 다음 단계: 신상·성인상·불상 등 상징물만 |
| 사진 배경 | 제작이 빠름 | 지시서가 금지 | 사용 안 함 |

권장: 건축(벽·기둥·천장·지붕)은 계속 코드로 만들고, **상징물만 GLB로 교체**한다. GLB는 R2에 두고 해당 공간에 들어갈 때만 받는다(Draco/meshopt 압축, KTX2 텍스처, 공간당 5MB 이하).

## 회원가입·로그인 (추후 추가 예정 — 지금부터 이 기준으로 만든다)

- **구조**: Cloudflare Workers(API) + D1(DB), 같은 Pages 프로젝트의 `functions/api/*`로 시작(무료 범위). 서버를 따로 두지 않는다.
- **가입 방식 후보**: 카카오·구글·애플 간편 로그인 + 이메일. 비밀번호를 직접 저장하는 방식은 피한다.
- **데이터 연결**: 지금 기기에만 저장하는 값(`oruvia-v1`: 닉네임, 관심 종교, MBTI·추천, 즐겨찾기, 최근 이용, 기도 노트, 알림 설정)을 같은 모양으로 계정에 동기화한다. 처음 로그인할 때 "이 기기 기록을 계정으로 옮길까요?"를 묻는다.
- **PujaTime 기록**(`pujatime-v1`, 나의 신전·푸자 기록)도 같은 계정으로 옮긴다(완전 통합 단계).
- **화면 자리**: 헤더 오른쪽 "프로필"이 로그인 전에는 "로그인", 후에는 닉네임. 마이페이지의 "계정 설정"에 가입·로그인·로그아웃·**계정 삭제**(앱 스토어 필수)를 둔다. 메뉴는 늘리지 않는다.
- **개인정보**: 기도 노트는 기본 비공개, 서버에 보낼 때도 본인만 읽게 한다. 고해 관련 내용은 계속 수집하지 않는다. 신앙 여부를 가입 조건으로 묻지 않는다.
- **비용**: D1 무료 범위(하루 읽기 500만·쓰기 10만 행), Workers 무료 하루 10만 요청에서 시작. 사용자가 늘면 Workers 유료($5/월).

- **다음 단계**: 사용자가 줄 교육 자료로 기초·심화 강의, 경전별 과정(성경 각 권, 바가바드 기타 등), 용어 사전 확장(발음·연관 용어), 이야기(스토리) 콘텐츠. 예수 석고상은 사진이 생기면.

## 5차 기획 반영 (2026-11-04): Experience First — 경험에서 시작

- **원칙**: 설명하기 전에 먼저 보여 준다. 공부시키기 전에 먼저 경험하게 한다. 관심이 생긴 사람에게만 더 깊은 정보를 준다.
- **메뉴**: 홈 · 탐험(3D 공간, `#/spaces`) · 알아보기(종교 이야기, `#/explore`) · 나의 공간 · 마이페이지. 주소는 그대로라 예전 링크가 깨지지 않음.
- **홈(P0, 완료)**: 큰 3D 공간 사진(네 종교가 6초마다 돌아가며, 날짜마다 시작 공간이 다름) + "새로운 세계를 만나보세요." + [공간 탐험하기] → 어디를 둘러볼까요?(종교별 공간 카드) → 다시 둘러보기(방문 기록) → 직접 경험해 보세요 → 이야기가 궁금해졌다면(질문형 짧은 글) → 나에게 맞는 공간 찾기(관심사 선택 + MBTI 선택). 교육 과정 카드는 홈에서 뺌(콘텐츠는 알아보기에 그대로).
- **문구**: 공통 입문 과정 → 종교 알아보기 첫걸음, 학습 과정 → 이야기, 진도 → 탐험 기록.
- **색**: 아이보리·크림·세이지, 갈색 버튼(#7A6652). 그림자와 테두리는 약하게.
- **P1 탐험(완료)**: `#/spaces/<종교>/<공간>` 입장 전 소개 — 사진·종교·예상 시간(실제 둘러볼 거리 기준 `MINUTES`)·이곳에서 해 볼 수 있는 것·이 공간 이야기·같은 종교 다른 공간. 목록의 '입장하기'는 바로 입장.
- **P2 공간 안(완료)**: 안내 지점 카드에 [더 알아보기], 안내 지점 3곳 이상 둘러본 뒤 공간마다 한 번 "이 공간에 담긴 이야기가 궁금하신가요?", 30초 넘게 머문 뒤 나가면 "○○을 둘러보셨네요" + 이야기·신앙 활동·같은 종교 다른 공간·다른 종교 공간.
- **P3 콘텐츠(완료)**: 종교마다 LEVEL 1 발견하기(질문형 4개, `discover`)를 이야기 탭 맨 위에. 강의는 이해하기(입문·기초) · 깊이 알아보기(심화) · 체험 묶음으로 거르기만 하고 순서를 강요하지 않음.
- **P4 개인화(완료, 1차)**: 홈 "이런 공간도 좋아할 것 같아요" — 많이 둘러본 종교의 안 가 본 공간 → 다른 종교의 안 가 본 공간, 그 종교 이야기 링크. 방문 기록만 쓰고 신앙을 짐작하지 않는다고 표시.
- **남은 것**: 공간 안 오브젝트를 직접 눌러 설명 보기(지금은 다가가면 뜨는 안내 지점 방식), 관심 콘텐츠 저장, 영어 강의 번역, 도우미 캐릭터(보류).
